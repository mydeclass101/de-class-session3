**สถานการณ์:** ห้องสมุดประจำคณะต้องการเก็บข้อมูลหนังสือแทนสมุดจด
ส่งงานเป็นไฟล์ `A1_<ชื่อ>.sql` ที่ **รันจากบนลงล่างได้โดยไม่ error และรันซ้ำได้**
ทุกข้อให้เขียน comment บอกเลขข้อ

## ส่วนที่ 1: DDL (40 คะแนน)

1. สร้างตาราง `books` ใน `lab_<ชื่อ>` ให้มีข้อมูลต่อไปนี้ เลือก data type ให้เหมาะสมเอง
   | ข้อมูล | กฎ |
   |---|---|
   | รหัสหนังสือภายใน | เลขรันอัตโนมัติ, primary key |
   | ISBN | 13 หลักพอดี, ห้ามซ้ำ, ห้ามว่าง |
   | ชื่อหนังสือ | ห้ามว่าง, ภาษาไทยได้ |
   | ผู้แต่ง | ห้ามว่าง |
   | หมวด | ต้องเป็นหนึ่งใน `novel`, `science`, `business`, `kids` |
   | ปีที่พิมพ์ | ห้ามน้อยกว่า 1900 |
   | จำนวนเล่มในห้องสมุด | ไม่ติดลบ, ถ้าไม่ระบุ = 1 |
   | ราคา | ทศนิยม 2 ตำแหน่ง (เงิน) |
   | วันเวลาที่บันทึก / แก้ไขล่าสุด | ระบบใส่ให้อัตโนมัติ, แก้ไขล่าสุดต้องเปลี่ยนเองเมื่อ UPDATE |
2. ใช้ `DESCRIBE` แสดงโครงสร้างตาราง
3. เขียน INSERT ที่ **ตั้งใจให้ละเมิดกฎ** 3 คำสั่ง (คนละกฎ) ใส่เป็น comment และเขียนว่าคาดว่าจะเจอ error อะไร

## ส่วนที่ 2: DML (40 คะแนน)

4. INSERT หนังสือ **8 เล่มด้วยคำสั่ง INSERT เดียว** (อย่างน้อย 1 เล่มไม่ระบุจำนวนเล่ม เพื่อใช้ค่า default)
5. ห้องสมุดซื้อหนังสือหมวด `kids` เพิ่มหมวดละ 2 เล่ม: UPDATE จำนวนเล่มทุกเล่มในหมวดนี้
6. ราคาหนังสือที่พิมพ์ก่อนปี 2010 ลดลง 20%: UPDATE ด้วยคำสั่งเดียว
7. หนังสือ 1 เล่มสูญหาย: ลบออก (แสดง SELECT ก่อนลบเพื่อยืนยันว่าลบถูกเล่ม)
8. เพิ่มคอลัมน์ `shelf_code` (เช่น `A-01`) ด้วย ALTER แล้ว UPDATE ให้ทุกเล่มมีค่า (ใช้ CASE ตามหมวดก็ได้)
9. แสดงให้เห็นว่า `updated_at` ของเล่มที่ถูกแก้เปลี่ยนไป แต่เล่มที่ไม่ถูกแก้ไม่เปลี่ยน

## ส่วนที่ 3: Transaction (20 คะแนน)

10. จำลองการ "ย้ายเล่ม" หนังสือ 1 เล่มจากเล่ม A ไปเพิ่มจำนวนให้เล่ม B (ลดของ A 1, เพิ่มของ B 1) ใน transaction แล้ว COMMIT
11. เริ่ม transaction ใหม่ ลบหนังสือทุกเล่ม แสดงว่าตารางว่าง แล้ว ROLLBACK แสดงว่าข้อมูลกลับมาครบ
12. ตอบเป็น comment (2–3 บรรทัด): ต่างกันอย่างไรระหว่าง `DELETE FROM books` กับ `TRUNCATE TABLE books` และในงาน pipeline ควรใช้แบบไหนเมื่อไร
