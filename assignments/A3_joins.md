# Assignment A3: Joins (หลังบทที่ 5)

รัน `A3_seed.sql` ก่อน (mini shop จากบทที่ 5 + ลูกค้า/ออเดอร์เพิ่ม)
ตาราง: `customers`, `products`, `orders`, `order_items`, `payments`
ส่งเป็นไฟล์ `A3_<ชื่อ>.sql`: 1 ข้อ = 1 query พร้อม comment

1. รายการ order ที่ `completed` พร้อม `customer_code`, ชื่อลูกค้า และจังหวัด เรียงตามเวลาสั่ง
2. ลูกค้า **ทุกคน** พร้อมจำนวน order และยอดซื้อรวม (ไม่นับ order ที่ `cancelled`) คนที่ไม่เคยซื้อต้องแสดง 0 ไม่ใช่ NULL
3. ลูกค้าที่ **ไม่เคยมี order ที่ completed เลย** (รวมคนที่ไม่เคยสั่ง และคนที่สั่งแต่ยกเลิก)
4. สินค้าที่ **ไม่เคยขายได้** (order ที่ `cancelled` ไม่นับว่าขายได้)
5. ยอดขาย (ไม่นับ cancelled) แยกตามหมวดสินค้า พร้อมจำนวนชิ้น
6. บรรทัดสินค้าที่ขาย **ต่ำกว่าราคาปกติ** ใน `products` แสดง order_number, sku, ราคาปกติ, ราคาที่ขาย, ส่วนต่าง
7. สำหรับทุก order: ยอดสินค้ารวม, ยอดที่จ่ายสำเร็จ, จำนวนครั้งที่จ่ายไม่ผ่าน (**ระวัง fan-out**: ตรวจ order 104 และ 109 ด้วยมือว่าตัวเลขถูก)
8. **(Data quality)** order ที่ `completed` แต่ **ไม่มี payment ที่ success**: ควรได้กี่แถว ทำไม query แบบนี้ถึงเป็น DQ check ที่ดี
9. timeline ของลูกค้า `CUS-0000002` รวม event จาก orders และ payments ด้วย `UNION ALL` เรียงตามลำดับ
10. จังหวัดที่มียอดขาย completed สูงสุด และยอดเท่าไร (ถ้าเสมอกัน ให้แสดงทุกจังหวัดที่เสมอ)

**คำถามท้ายบท (ตอบใน comment):** ถ้าเขียนข้อ 2 ด้วย `INNER JOIN` แทน `LEFT JOIN` ผลจะต่างอย่างไร
และถ้าใส่เงื่อนไข `status <> 'cancelled'` ไว้ใน `WHERE` แทน `ON` จะเกิดอะไรขึ้น
